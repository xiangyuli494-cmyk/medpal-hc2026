## 2 为什么是数字媒体设计·交互设计

1. **材料要求完全对得上**。官方要「高保真设计图 + 交互流程图 + 演示视频」，正是我们手里东西该被翻译成的形状；换成产品设计就得交三视图和工艺说明，换成交叉创新就得交完整提案——都不是我们的强项形态。
2. **原型验证目标明确**。七屏需连成可点击演示，检查三通道、确认与纠错、求助与归还；当前没有可核验的完整原型交付，不能把目标写成已实现能力。
3. **评委能看懂差异化**。同一组里，别人做的是"好看的 App"，我们做的是"三种身体条件、三套交互契约、同一台公共设备"。这个差异在第一张图就能看出来。

## 3 作品定位（一句话版本，全组统一口径）

> **一台在门诊服务台借出、离院前归还的手持陪诊机，替不会用手机的老人走完院内全流程。**

对外**不说**的话：

| 不说 | 改说 |
| --- | --- |
| 医疗决策智能体 | 医嘱回放 / 流程协助 |
| 分诊、诊断、建议用药 | 帮您把医生的话记下来、讲清楚 |
| AI 判断 | 医生说……（原话为准） |
| 老人不会用手机是他们的缺陷 | 设备不该要求用户先学会用手机 |

## 4 三个差异点（答辩与展板都围绕这三条）

1. **通道即契约，不是换肤**
   老人：大字 + 记忆辅助 + 复述校验；视障：语音获取信息、导航无需点按、语音确认与长按求助；听障：文字优先 + 「替我说」把文字念给医生听。
   三套不是同一个界面的三种配色，而是三种完全不同的交互契约。
2. **系统不会猜**
   演示注入识别置信度 0.41，用「心内 / 心衰」两个候选说明不确定时需要用户确认。该数值是演示输入，不代表实测识别性能；不增加剂量选择或用药建议场景。
3. **AI 是可被检查的**
   设计上要求区分原始信息、呈现与用户确认，并展示纠错和退出路径。这是可检查性要求；当前未交付真实模型或自动红线校验实现，不声称已具备完整审计能力。

## 5 与小暖形象的关系

小暖是设备上的虚拟陪伴角色，**不是客服弹窗**，也不是医生。

- 不穿白大褂、不戴听诊器、不出现任何医疗器械
- 五种表情：待机 / 说话 / 倾听 / 关切 / 高兴
- 形象上就先说清楚：她陪您跑流程，不负责看病
