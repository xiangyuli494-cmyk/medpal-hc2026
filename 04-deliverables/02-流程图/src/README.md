# 流程图源文件（Mermaid 文本）

这里放流程图的**源**，不是导出图。规矩四条：

1. **改图必须改源。** 导出 PDF 与 `.mmd` 不一致的，按没做算。
2. **一个图一个文件**：`主流程.mmd`、`三通道.mmd`、`异常降级.mmd`。不新建第四个，也不合并。
3. **导出放上一层**：`04-deliverables/02-流程图/小暖_流程图_主流程.pdf`，文件名去掉 `.mmd` 后缀。
4. **评审看源文件**。PR 里 T1 逐行看的就是这些文本，不是 PDF——PDF 不能逐行批注。

## 为什么用 Mermaid 而不是 Visio / draw.io / Figma

| | Mermaid `.mmd` | draw.io | Visio / Figma |
| --- | --- | --- | --- |
| GitHub 渲染 | ⚠️ 只渲染 `.md` 里的 mermaid 围栏；独立 `.mmd` 点开是纯文本，预览走 VS Code 插件 / mermaid.live / mmdc | ❌ 要下载 | ❌ 要下载 |
| PR 里逐行批注 | ✅ | ⚠️ XML 能看但难读 | ❌ 二进制 |
| 改一个措辞 | 改一行字 | 拖一个框 | 拖一个框 |
| 文件大小 | 1–3 KB | 几十 KB | 几百 KB–几 MB |

选 `.mmd` 的理由只有两条，都不依赖"GitHub 能看图"：**PR 里能逐行批注**、**改一个措辞只改一行字**。

代价是排版控制力弱：不能精确摆位，GitHub 页面也不出图。**流程图不需要精确摆位**——它要的是"箭头没错、判断点都有两条出路"；A3 成品的版式由 `02-design/06-流程图视觉规范.md` 在 Figma 里另做一遍，不拿 mermaid 渲染图当交付图。

## 怎么本地出图

```bash
npx -y @mermaid-js/mermaid-cli -i src/主流程.mmd -o 小暖_流程图_主流程.pdf
```

或者把 `.mmd` 内容贴进 <https://mermaid.live>，直接导出 SVG / PNG / PDF，不用装任何东西。

## 导出成品说明（G2 那三份 PDF）

上一层的 `小暖_流程图_*.pdf` 是用上面那条命令从 v1.3 源文件直接导出的，**内容与 `.mmd` 逐字一致**（验收第 ④ 条）。

- **页面随图自适应**，不是固定 A3：主流程是竖向长链（约 150×684mm）、三通道是 3 泳道横向铺开（约 212×12mm，极扁）、异常降级接近横版（212×115mm）。这是 Mermaid 自动排版的形状，不是导出错误。
- **A3 横版成品**（主流程四条横带 17 框、三通道每行 5 节点只画 07–09 段）按 `02-design/06-流程图视觉规范.md` 在 **G3（11-16 后）** 出，那份是手绘排版，不用 Mermaid 导出。
- 改源文件后必须重导三条命令，PDF 不许比 `.mmd` 旧。
