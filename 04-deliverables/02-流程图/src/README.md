# 流程图源文件（Mermaid 文本）

这里放流程图的**源**，不是导出图。规矩四条：

1. **改图必须改源。** 导出 PDF 与 `.mmd` 不一致的，按没做算。
2. **一个图一个文件**：`主流程.mmd`、`三通道.mmd`、`异常降级.mmd`。不新建第四个，也不合并。
3. **导出放上一层**：`04-deliverables/02-流程图/小暖_流程图_主流程.pdf`，文件名去掉 `.mmd` 后缀。
4. **评审看源文件**。PR 里 T1 逐行看的就是这些文本，不是 PDF——PDF 不能逐行批注。

## 为什么用 Mermaid 而不是 Visio / draw.io / Figma

| | Mermaid `.mmd` | draw.io | Visio / Figma |
| --- | --- | --- | --- |
| GitHub 渲染 | ⚠️ 只渲染 `.md` 里的 mermaid 围栏；独立 `.mmd` 点开是纯文本，预览走 VS Code 插件 / mermaid.live / mmdc | ❌ 要下载 | ❌ 要下载 |
| PR 里逐行批注 | ✅ | ⚠️ XML 能看但难读 | ❌ 二进制 |
| 改一个措辞 | 改一行字 | 拖一个框 | 拖一个框 |
| 文件大小 | 1–3 KB | 几十 KB | 几百 KB–几 MB |

选 `.mmd` 的理由只有两条，都不依赖"GitHub 能看图"：**PR 里能逐行批注**、**改一个措辞只改一行字**。

代价是排版控制力弱：不能精确摆位，GitHub 页面也不出图。**流程图不需要精确摆位**——它要的是"箭头没错、判断点都有两条出路"；A3 成品的版式按 `02-design/06-流程图视觉规范.md` 由排版脚本另做一遍，不拿 mermaid 渲染图当交付图。

## 怎么本地出图

```bash
npx -y @mermaid-js/mermaid-cli -i src/主流程.mmd -o 小暖_流程图_主流程.pdf
```

或者把 `.mmd` 内容贴进 mermaid.live（浏览器里搜站名即可），直接导出 SVG / PNG / PDF，不用装任何东西。

## 导出成品说明（三份 PDF）

上一层的 `小暖_流程图_*.pdf` 是 **A3 横版 420×297mm 单页**（2026-11-18 起，commit 94947d1；命名按 `06-流程图视觉规范.md` §8，不带 `_A3`）。成品不是 Mermaid 直接导出，而是按视觉规范（§2 节点尺寸 / §4 四档字号 / §5 语义色板 / §7 页眉页脚）由 T3 的排版脚本生成，**内容与 `.mmd` 逐格一致**（验收第 ④ 条）——改源必须重出图，PDF 不许比 `.mmd` 旧。

- 变更依据：G2 阶段（2026-11-17）曾用上面的 mmdc 命令导出自适应页面 PDF（主流程约 150×684mm、三通道约 212×12mm、异常降级 212×115mm）。T1 规范 §8 规定交付为 A3 单页、命名不带 `_A3`，故 11-18 整批重制替换；mmdc 命令此后只用于源文件快速预览，**不作交付**。
- 页脚「源 <短SHA>」是成品与源对得上的凭据（验收 ⑧），保留真实文字层；其余内容按 §8 转曲要求由排版脚本输出矢量图形。
