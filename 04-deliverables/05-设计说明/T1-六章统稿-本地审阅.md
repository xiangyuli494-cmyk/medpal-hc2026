# 小暖 · 院内智慧陪诊终端

<!-- page:P01 -->
## 交互设计说明 · 本地审阅稿

一台在门诊服务台借出、离院前归还的手持陪诊设备，帮助使用者获取当前步骤、表达需求，并确认医生交代的事项。

适配设备：1024×600横屏手持终端。演示范围为常规门诊，包含通用、视障与听障三种交互通道。

本稿由T1整理结构、证据和交互边界，供本地审核。六章正文与12页页序已编排；正式屏幕、流程配图及行为测试尚未齐全，不能作为最终参赛文件提交。

阅读顺序：背景 → 研究 → 方案 → 交互 → 技术可行性 → 边界与伦理。末两页列出验证限制和来源。

当前设计目标：一次只处理当前任务；同意、拒绝和纠错都有出口；家属通知由使用者决定；设备不替代医护判断。

本稿没有采用访谈对象的姓名、亲属称谓、学校或医院名称，示例医嘱与金额均为演示内容。

## 一、背景：把分散的步骤接起来

门诊过程需要在建档、候诊、诊室、检查和缴费等环节之间切换。项目用11个节点梳理这些环节，作为设计模型，并不代表所有医院均采用相同流程。[S3]

在已整理的访谈中，一位家属说「问人，一般都是问人」，另一位受访者提到「看那个指示牌，或者问那个导医去下一步」。两条记录支持继续探索连续指引，但不足以说明现有导诊在所有场景都失效。[S1，卡1、3]

小暖采用服务台借出式终端，让患者在当前任务上获取信息。它不要求先安装应用或寻找多层菜单。是否方便借用、携带与归还，仍须实际测试；卡10关于押金和损坏赔付的顾虑说明，借用流程本身也可能成为障碍。[S1，卡10]

设计的覆盖范围为常规门诊流程协助。急诊、住院管理、诊断与治疗选择不在本次范围内。[S6]

## 二、研究：先说明样本与材料

研究材料来自三位熟人受访者的记录：A为70岁女性，B为62岁男性家属，C为另一位长辈，年龄尚待补充。B谈到的是陪同或了解的就诊经历，不能计作患者本人的直接陈述。[S1]

原话卡共12张。A的材料标为逐字文字记录，B标为录音转写并经访谈人确认，C标为即时访谈文字。录音材料的实际同意范围、原始文件删除情况应由采集人核对，不由统稿代签。[S1]

这些材料用于提出设计问题，不用于统计推断。当前没有视障、听障目标用户的直接访谈或真实院内试用证据，不能据此宣布三通道已获得目标人群验证。

卡4「有，回家都想不起来」可支持继续探索医嘱记忆辅助。卡5只谈上次就诊时间，其含义不能扩大为「医嘱更容易丢」。C对费用问题回答「没有」，也不能写成「费用不透明使老人放弃检查」。[S1，卡4、5、8]

## 三、方案：同一任务，三种信息获取方式

通用通道以大字和简短信息呈现当前任务；视障通道用语音获取信息和确认；听障通道以文字获取信息，并允许设备把选定短句念给医生。医生回复须有文字呈现，不能要求听障使用者依赖声音获取回复。[S3、S4]

入口支持选择通道和重选。入口屏任意位置长按2秒进入语音通道；进入后须松手，避免同一次持续按压被误认为求助。此时序为待验证的交互要求。[S3]

视障导航无需寻找屏幕按钮。进入02后，任意位置长按1.5秒用于求助，说「再说一遍」用于重播；长按不兼任确认或重播。设备只描述电梯方位，不承诺自动按电梯。[S3、S4]

03允许从六个短句中选择表达，再执行「念给医生听」。选句和执行分开计步；不能把多次选句也计算成「全程一次点击」。[S4]

图位04：01入口分流；图位05：02视障语音；图位06：03替我说。三图均待正式导出。本页三栏只用于说明通道差异，不代表三种通道已完成实测。

## 三、方案：复述确认与费用解释

04把已记录的医生交代呈现给使用者确认。「对，就是这样」与「不对，我再说一遍」同等可见；确认动作只表示本次记录得到认可，不表示系统已获得诊断权限。[S4]

演示医嘱统一为「抽血要空腹、心电图；都在二楼，先抽血再做心电图」。这是虚构演示内容，不能被当作对实际患者的检查建议；视频和家属通知不得混入旧稿中的B超或三楼。[S3、S4]

05将费用先分为总额、医保支付和个人支付：386 = 253 + 133。明细中153 + 125 + 108 = 386；医保支付153 + 100 = 253；个人支付25 + 108 = 133。[S4]

这些数值只用来验证信息呈现是否自洽，不代表真实报销规则或对某位患者的结算承诺。页面保留「以医院结算单为准」。设备解释金额，不代扣费用。[S4、S6]

图位07：04复述校验；图位08：05医保三宫格。待T2正式图；需在审阅时核对两个确认出口、三组数字与来源说明。

## 四、交互：每次决定都保留拒绝出口

11节点是内容模型，七张图是用于展示关键机制的屏幕样本，不能混用两套编号。07进诊室按已经选定的通道呈现，不要求患者再次做通道选择。[S3、S4]

视障通道用明确语音答复确认。取号、缴费跳转和家属通知等决定，不能以播报结束或用户沉默作为同意。检查规划保留「等等」，缴费保留「再看看」，家属通知保留「不发」。[S3]

实际支付仍在医院原有渠道完成。本作品只展示费用解释和前往缴费的引导，不宣称终端完成付款。

有未完成检查时先回到检查规划，再给出下一段导航；不让患者在同一导航段循环。归还时若仍有未完成事项，先列出清单、询问是否发送，再确认清空；拒绝发送不阻止正常归还。[S3]

## 四、交互：不确定时停下来求证

项目为六类情形规定出口：断网、识别不确定、问题越界、长时间无操作、低电量，以及归还时流程尚未完成。[S3]

E1用「心内 / 心衰」两个同等呈现的候选展示求证。置信度0.41与阈值0.6均为演示参数，当前没有校准实验，不应解释为实际模型的错误概率或可靠性指标。看不见屏幕时须播报候选并接受语音答复。[S3、S4]

问题越界时转向人工服务，不能自动生成医疗建议。90秒无操作时保留当前任务，不催促或将沉默视为确认。低电量时引导服务台处理，不宣称借用记录已实现自动跨设备转移。

断网只可继续展示预先缓存且仍有效的信息；实时叫号、未知路况、最新费用和人工接入不能保证离线可用。缺失或过期信息应提示人工核实。[S3]

图位10：异常降级图与E1画面组合。需检查每条判断的两个出口、人工求助可达性，以及E1候选无默认选择。

## 五、技术可行性：演示内容与部署条件

本阶段交付为交互设计概念。文档规则能够被演示，但不构成已部署系统的能力证据。真实识别、室内定位、医院数据接口、加密和安全删除均须另行实现并验证。[S5、S6]

| 能力 | 本阶段的演示方式 | 实际部署前提 |
| --- | --- | --- |
| 语音输入与代说 | 预设文本、录音或人工触发 | 嘈杂环境识别、隐私、音量与延迟测试 |
| 分段路线 | 虚构路径、预设步数 | 无障碍路线核对、障碍变化与定位误差测试 |
| 叫号与费用 | 固定示例数据 | 院方授权接口、更新时点与失效处理 |
| 家属节点通知 | 推送卡示意 | 使用者同意、接收方确认、撤销与送达验证 |
| 本地数据处理 | 展示清空确认与完成反馈 | 加密、备份/日志范围和删除效果验证 |

本次不提供未经采购与实现依据支持的成本、识别准确率、导航误差或数据安全达标数字。

## 六、边界与伦理：控制权留给使用者

小暖辅助获取流程信息、表达需求和确认记录，不提供诊断、用药建议或检查选择，不替代医护、家属签字和知情同意。小暖形象不使用白大褂、听诊器等暗示医护身份的元素。[S6]

家属端只报已发生的节点，不显示实时位置、轨迹或未经确认的检查结果。卡11、12仅是一个样本的偏好，不能据此默认开启通知；发送前需明确同意，之后可关闭。[S1、S3、S4]

06仍包含在七张交付图中的一张横版画布内，手机通知卡是示意，不额外增加第八张设备屏。通知中的医嘱、时间和完成状态必须与设备端对应。[S4]

归还清空是数据最小化的设计要求。视频里的「已清空」只展示交互反馈，不能据此断言备份、日志或存储介质已安全删除。正式部署须说明并验证保留范围。[S6]
