# 设计原则

> 这五条是全组的宪法。任何一屏、任何一个按钮，如果违反其中一条，就是错的——不管它多好看。

## 原则一：设备不该要求用户先学会用它

老人失败的原因不是"不会用手机"，是**手机这种形态本身要求了它没有的能力**：小屏、精细触控、多层菜单、账户体系、文字阅读、持续注意力。

所以我们做的不是"把 App 做大字号"，是**换掉形态**：横屏、大按钮、一次只问一件事、没有登录、服务台借出、离院归还。

> 判据：如果一个 78 岁、手抖、老花、不识字的人需要先看说明，那这屏就是失败的。

## 原则二：一个通道，一套契约

三种使用者不是三种配色，是三种完全不同的交互契约。切换通道时，**不是换皮，是换规矩**。

| 通道 | 契约 | 禁止出现 |
| --- | --- | --- |
| 通用（老人） | 大字 + 记忆辅助 + 复述校验 | 二级菜单、图标无文字、滑动操作 |
| 视障 | 全程语音、零交互、步数化导航 | 任何需要触摸才能继续的步骤 |
| 听障 | 文字优先、视觉确认、「替我说」 | 只有声音的提示、纯语音播报 |

## 原则三：系统不猜

医疗场景里，"猜错"的代价不是难看，是危险。所以遇到不确定，系统必须**把不确定说出来**。

| 场景 | 错误做法 | 我们的做法 |
| --- | --- | --- |
| 语音识别置信度低（0.41） | 硬猜一个词 | 屏幕上标红「您说的是"心内"还是"心衰"？点一下」 |
| 剂量 0.5g / 5g | 自动补全 | 「医生说 0.5 克，一天两次——我念得对吗？」 |
| 手写病历模糊 | OCR 猜 | 只显示"手写内容，请让医生看" |
| 用户说的话超出范围 | 硬答 | 「这个我不能答，我帮您叫护士」 |

## 原则四：AI 是可被检查的

屏幕上出现的每一句话，都能展开成五段：**事实 → 模板 → 润色 → 红线校验 → 出口**。

- 事实：从哪个节点、哪条数据来的（含节点 id、时间）
- 模板：没调 LLM 的那部分，逐字可对照
- 润色：LLM 只做语气改写，不改事实
- 红线：是否含医学结论、是否越界
- 出口：最终那句话

> 这不是工程炫技，是设计上的诚实：让陪同的家属、让护士，能当场问"你凭什么这么说"。

## 原则五：陪伴是可关闭的

小暖存在的意义是减少孤独带来的错误，不是增加黏性。

- 任何一个功能都能被关掉，包括小暖本人
- 不做积分、不做打卡、不做"您已连续使用 12 天"
- 离院一键清空本地数据
- 家属端只报节点，不做实时定位

> 判据：如果这个功能是为了让用户多留一会儿，删掉它。

## 附：语言规范（文案层）

| 不要写 | 要写 |
| --- | --- |
| 请点击「下一步」按钮 | 点一下右下角 |
| 操作失败，请重试 | 没连上网，我再说一遍 |
| 您已成功预约 | 约好了，4 月 17 日早上 9 点 40 |
| 系统检测到您…… | 我看到您…… |
| 温馨提示 | （直接说事，不寒暄） |
| 请前往 3 楼内科诊区 | 往前走十八步，右手边第三间 |

原则：**动词 + 方位 + 数量，不用抽象名词。**
