# 信息架构

## 1 一台设备，11 个节点，一条线

设备只有一个"页面"——当前该做的那件事。没有底部导航、没有个人中心、没有返回首页。

```
借出开机
  └─ 01 入口分流（选人）
       ├─ 02 建档 / 复诊（读卡，或人脸）
       ├─ 03 到达定位（beacon / 手工选）
       │    └─ 04 今日行程播报
       │         ├─ 05 取号排队
       │         ├─ 06 候诊（告知第几位 / 大约多久）
       │         ├─ 07 进诊室（替我说 / 复述校验）
       │         ├─ 08 检查规划（空腹、先后顺序）
       │         ├─ 09 执行与导航（步数化 / 大字地图）
       │         ├─ 10 缴费取药（医保三宫格）
       │         └─ 11 小结与回家（家属推送）
       └─ 归还 → 一键清空 → 下一位
```

## 2 三通道在同一节点上的差异（11 节点 × 3 通道 = 33 格，已填满）

同一个节点，三种人看到的东西不一样，但**走的是同一条线、同一个位置、同一次决定**。
每格写的是"这一格怎么呈现 + 用户做什么动作"，不是形容词。

| 节点 | 用户只需做一个决定 | 通用（老人） | 视障 | 听障 |
| --- | --- | --- | --- | --- |
| 01 入口分流 | 今天是谁来看病 | 三个大磁贴（老人自己来 / 眼睛看不见 / 耳朵听不见），点一下直接进，选错可重选 | 长按屏幕任意处 2 秒进入；进入时只说一句"松手就进，不用找按钮" | 三磁贴 + 一行"不用听，看字就行" |
| 02 建档 / 复诊 | 是不是第一次来 | 读身份证建档 / 复诊"还是上次那位王医生吗？"两个大按钮 | 语音引导"把身份证放到机器上"，读卡完成念出姓名让患者确认 | 放卡位置用图示 + 文字，完成后大字"好了" |
| 03 到达定位 | 要不要改（默认不改） | 自动识别，大字"您在门诊大厅"；认错了点一下改 | 播报"您在门诊大厅，右手边是导诊台"，不要求任何操作 | 文字 + 方向图标，位置名最大号字 |
| 04 今日行程 | 从哪件开始 | 三行大字，第一件高亮，主按钮"从这件开始" | 念完三件，问"从第一件开始，好吗？" | 文字时间轴，三件一次看完 |
| 05 取号排队 | 现在取号吗 | "要我帮您取号吗？" → 取 / 先不取 | 语音问，答"好"即可；取到号念出号码与前面人数 | 文字确认 + 号码大字 + 前面人数 |
| 06 候诊 | 继续等 / 去走动 | "前面还有 3 位，大约 20 分钟" | 只说剩余人数，不说分钟（数字比时间可靠） | 文字 + 倒计时条，人数与条同步 |
| 07 进诊室 | 说 / 复述（二选一） | 复述校验卡：「对，就是这样」/「不对，我再说一遍」 | 全程代说，患者只需按一次确认 | **替我说**（核心屏）：点一句 → 念给医生听 |
| 08 检查规划 | 先做哪项（顺序由系统给） | "先抽血，再做心电图"两件排好序，主按钮"带我去" | 念顺序 + 一句理由（"抽血要空腹，所以先做"） | 文字时序图，每项可点开看要求（空腹 / 憋尿） |
| 09 执行与导航 | 到了没有 / 继续走 | 大字方向 + 楼层图，只说当前一步 | 步数 + 左手右手（"往前走十八步"） | 方向图 + 距离（米） |
| 10 缴费取药 | 现在交 / 再看看 | 医保三宫格 + 一句人话 + 「去缴费」/「先不交，我再看看」 | 念金额，强调"医保替您付了大半"，问"现在交吗" | 三宫格 + 明细可点开，金额等宽对齐 |
| 11 小结与回家 | 要不要告诉家人 | "今天做了 3 件事，都做完了" + 一键推送家属 | 语音小结 + 下次复诊提醒，可重复收听 | 文字小结 + 推送预览（给家属看的那条） |

**填表规矩**（T3 按此画图，发现空格就打回）：

1. 每格必须写出**动作**（点 / 长按 / 答一个字 / 什么都不做），只写"语音提示""文字显示"不算填。
2. 视障列禁止出现"点击""按钮位置"这类依赖视觉的词；听障列禁止出现"听""语音提示"。
3. 同一节点三列的主按钮位置必须相同（右下 / 居中），只有措辞和呈现方式变。
4. 一个节点只允许一个决定；出现两个决定的节点，说明节点没切干净，回到第 1 节拆开。

## 3 导航结构（屏幕上真正存在的东西）

- **主键区**：屏幕下方固定 3–4 个大按钮，位置永不变（肌肉记忆）
- **状态区**：屏幕顶部一条细状态栏（已开机 / 当前位置 / 时间 / 联网）
- **说话区**：屏幕中央，一次只说一件事，最多两行
- **求助**：右下角常驻一个红色「求助」按钮，长按 1.5 秒人工接入（防误触）
- **没有的东西**：返回上一级（不需要）、关闭（不需要）、设置（藏在长按里）

## 4 一次任务的信息量上限（硬限制）

| 项 | 上限 | 理由 |
| --- | --- | --- |
| 同屏文字块 | 3 个 | 超过 3 块，老人开始跳读 |
| 单块字数 | 18 字 | 1024px 宽、40px 字，两行以内 |
| 同屏按钮 | 4 个 | 第 5 个开始出现选择困难 |
| 单步操作 | 1 次点击 | 任何需要"两步才能完成"的动作都要拆成两屏 |

## 5 状态清单（每屏必备）

每一屏都必须设计这五种状态，缺一就是没做完：

| 状态 | 例子 |
| --- | --- |
| 正常 | 一切顺利 |
| 加载 | 读卡中（不超过 2 秒，超时给话术） |
| 不确定 | "您说的是心内还是心衰？" |
| 出错 | "没连上网，我再说一遍"（不出现错误码） |
| 完成 | 明确的"做完了"，带下一步 |

## 6 与旧版信息架构的关系

旧版（`medpal/docs/specs/device-ia.md`，26K）是工程视角的节点树，11 个节点保留；
**改变的是呈现**：从"节点树 + 面板"变成"一次一件事的全屏"。
工程侧的结构复用，视觉与交互全部重做。
